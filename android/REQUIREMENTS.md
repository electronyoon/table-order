# android 요구사항 (명세만 — 미구현)

이 문서는 사용자가 지시한 요구사항을 구현 전에 기록한 것이다. **이 문서 자체는 코드를 만들지 않는다** — 실제 구현은 별도로 진행한다.

## 1. 품목 취소 제스처

`docs/design.md` §3에서 확정된 내용을 android 관점에서 다시 정리한다.

| 제스처 | 의미 | 모달 문구 | 결과 |
|---|---|---|---|
| 일반 탭 | 변심취소 | "'{메뉴명}'을 취소할까요?" [취소하기] / [돌아가기] | `order_item.status = CANCELED`만. 품절 처리 없음 |
| 길게 누르기 | 재고부족취소 | "'{메뉴명}'을 취소하고 오늘 하루 품절 처리할까요?" [품절 처리하고 취소] / [돌아가기] | `CANCELED` + 당일 품절 (한 트랜잭션) |

- **두 제스처 모두 확인 모달 필수** — 실수 방지 목적이므로 모달 없이 바로 처리되는 경로는 없어야 한다.
- API: `POST /admin/order-items/{orderItemId}/cancel`, body `{ "markSoldOut": boolean }` (`contracts/openapi.yaml` 참고).

## 2. 반응형 레이아웃 (태블릿 vs 폰)

동일 APK 안에서 화면 크기에 따라 레이아웃이 분기되어야 한다 (기기별 별도 빌드 아님).

- **태블릿 (넓은 화면)**: 일반 POS처럼 **테이블 현황**과 **조리대기목록**을 한 화면에 동시에 보여준다.
- **폰 (좁은 화면)**: **조리대기목록만** 보여준다.

### 미정 — 구현 시 결정 필요

이 요구사항은 사용자의 지시를 그대로 옮긴 것이고, 아래 세부사항은 아직 정해지지 않았다:

- "테이블 현황"에 정확히 어떤 정보를 표시할지 (테이블 라벨/사용중 여부만 vs 경과시간·주문금액 등 추가 정보 포함 여부). `docs/design.md` §2 ERD상 `store_table`(라벨) + `table_session`(status: OPEN/CLOSED, opened_at)이 근거 데이터로 존재한다.
- 태블릿/폰을 가르는 정확한 화면 크기 기준값(breakpoint).
- 태블릿 화면에서 테이블 현황과 조리대기목록의 배치 비율·상호작용(예: 테이블 탭 시 무슨 일이 일어나는지).
- `device.role`(PRIMARY/BACKUP, `docs/design.md` §5)과 이 반응형 분기의 관계 — 화면 크기 기반 레이아웃 분기와 role 값은 별개 축이다. 태블릿=PRIMARY, 폰=BACKUP이 일반적이겠지만 자동으로 묶이는 규칙인지는 미정.

## 3. 그 외 이미 design.md에 있는 화면 규칙 (변경 없음)

- 버튼은 취소/조리완료 두 개뿐, 접수 단계 없음 (§3)
- 조리완료는 주문 단위 (남은 ACTIVE 품목 전체 완료 처리)
- 모든 품목이 취소되면 주문도 자동 COMPLETED
- 대기열 폴링 주기 15~30초 (§5)
